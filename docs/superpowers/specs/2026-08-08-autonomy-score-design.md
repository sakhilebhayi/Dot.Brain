# Autonomy Score Computation

## Context

`brain.autonomy.md` §3 defines the Autonomy Score formula (11 weighted categories, unmeasured category scores 0, never excluded) but does not say how a category's score is actually derived from real evidence — that mapping didn't exist because no real evidence existed yet. The Platform Autonomy Classification sub-project (29 platform audits, all committed) now provides that evidence. This sub-project builds the scoring layer on top of it.

**Reality check carried over from the prior sub-project:** 14 of 29 platforms have at least one real Level 1 process; the rest have none. Only `dot-agents` has a real Level 2 process. Cushion (real financial-resilience visibility) exists on 3 platforms. Marketing, Sales, Customer Experience, Finance, and Learning have essentially zero real signal anywhere in the ecosystem. The score this sub-project produces will be low almost everywhere — that is the correct, honest output, not a defect in the design.

## Goal

Ship two things:

1. `platforms/autonomy-signals.json` — one consolidated, hand-built data file listing the real boolean/count signals for all 29 platforms plus Dot (ecosystem layer), Houz of Sax Trust, and BluPin.
2. `services/autonomy-score/` — a small Node CLI (mirrors `services/market-research/` and `services/intervention-log/`'s shape) that computes and prints the per-entity, per-category Autonomy Score from that data file, per the formula table below.

## Data layer: `platforms/autonomy-signals.json`

One JSON array, one object per entity:

```json
{
  "entity": "dot-finance",
  "kind": "platform",
  "level_1_count": 0,
  "level_2_count": 0,
  "has_cicd": false,
  "has_cushion_dimension": true,
  "has_security_ci_check": false,
  "verified_infrastructure_pass": true,
  "audited_date": "2026-08-08"
}
```

`kind` is `"platform"` for the 29 registered platforms, or `"ecosystem-entity"` for the three non-platform rows: `houz-of-sax`, `blupin`, and `dot` (the Dot ecosystem layer itself — distinct from any individual platform; its own signals reflect Dot.Brain's own repository, already captured in `platforms/dot-brain.md`'s classification section).

**Provenance:** every field is read directly from the already-committed `## Autonomy Classification` section (and, for `verified_infrastructure_pass`, the `## Verified Infrastructure State (2026-08-07)` section where present) in each platform's `platforms/<id>.md`. No new repository access, no new subagent dispatch — this file is a structured extraction of prose that already exists and was already reviewed. Houz of Sax and BluPin get an entry with every boolean `false` and both counts `0` — explicit zeros, not an omitted row, per `brain.autonomy.md` §7 (never hide a weak entity by leaving it out).

**Staleness is explicit, not hidden:** `audited_date` on every row lets the report state plainly how old each signal is. This file is not auto-regenerated by re-reading platform repos; it is a snapshot of the 2026-08-08 audits until a future sub-project re-audits and updates it by hand.

## Scoring layer: `services/autonomy-score/`

### Category formula table (binary, one signal per category — no double-counting)

| Category | Weight | Formula | Rationale |
|---|---:|---|---|
| Governance | 10% | 100 if `level_2_count > 0` else 0 | A real Level 2 process is direct evidence of decision-rights infrastructure (Context→Evidence→Risk→Recommendation→Proposed Action). |
| Operations | 10% | 100 if `level_1_count > 0` else 0 | Direct reuse of the classification data — can the operator stay out of some routine loop. |
| Technology | 10% | 100 if `has_cicd` else 0 | The one uniform automation signal every audit explicitly checked and cited. |
| Marketing | 10% | always 0 | No platform audit found any real marketing automation. |
| Sales | 10% | always 0 | No platform audit found any real sales-pipeline automation. |
| Customer Experience | 10% | always 0 | No platform audit found any real automated support/onboarding beyond stock framework scaffolding, which was explicitly excluded as end-user self-service, not operator automation. |
| Finance | 10% | always 0 | Cushion's evidence is spent on Resilience (below), not duplicated here — no other real Finance-operations automation exists on any platform. |
| Security | 10% | 100 if `has_security_ci_check` else 0 | A narrower, distinct signal from Technology's general CI check, so one CI workflow can't inflate two categories. |
| Resilience | 10% | 100 if `has_cushion_dimension` else 0 | Cushion is explicitly framed in `brain.cushion.md` as business shock-absorption visibility — assigned here exclusively. |
| Knowledge | 5% | 100 if `verified_infrastructure_pass` else 0 | Whether the platform's own documented knowledge has been confirmed against its real repository — a knowledge-accuracy signal, kept distinct from Security. |
| Learning | 5% | always 0 | The Owner Intervention Log has one test entry, not real production learning; no platform feeds real outcomes back through `brain.learning.md`'s loops yet. |

**The double-counting rule, stated once for the whole table:** every real piece of evidence this sub-project has (cushion existing, a CI workflow existing, a verified-infrastructure pass having happened) feeds exactly one category, chosen by best conceptual fit. No signal is reused across two categories to inflate the weighted sum — this is the specific mechanism that prevents a single real artifact (e.g. the 2026-08-07 patching pass) from silently boosting both Security and Knowledge.

### Entity score

`score(entity) = Σ (category_weight × category_formula(entity))`, expressed as a 0–100 number matching the weight percentages summing to 100.

### `dot` ecosystem-level score

Computed two ways, both always shown together, never one without the other:
- **Per-platform breakdown**: all 29 platform scores, listed individually (per §4/§7 of `brain.autonomy.md` — never hidden behind an average).
- **Ecosystem average**: the unweighted mean of the 29 platform scores, labeled explicitly as an average, not presented as if it were `dot`'s own independent score. `dot`'s own entity row (Dot.Brain's own repository, from `platforms/dot-brain.md`) is reported separately from this average — they measure different things and must not be conflated.

### CLI (`services/autonomy-score/src/cli.js`)

```
autonomy-score report                    # full breakdown: every entity, every category, weighted total
autonomy-score report --entity=dot-finance   # one entity's breakdown
autonomy-score report --entity=dot        # the 29-platform average + Dot.Brain's own entity score, shown separately
```

Output is plain text, one section per entity: category-by-category (`100` or `0`, with the category name and formula's plain-English reason inline — e.g. `Operations: 0 (no real Level 1 process found in the 2026-08-08 audit)`), then the weighted total, then a one-line staleness note citing `audited_date`.

### Testing

`test/score.test.js` — unit tests against the pure `score.js` computation (not the CLI): each category formula independently (true/false → 100/0), the full weighted-sum for a hand-computed fixture entity, the ecosystem-average computation, and that Houz of Sax / BluPin's all-zero fixture produces a 0 total rather than an error or an excluded/undefined category. No CLI-level tests beyond a manual end-to-end run, matching this repository's established precedent for these small services.

## Explicitly out of scope for this sub-project

- Any dashboard UI (`brain.autonomy.md`'s §19-equivalent from the original brief) — this ships a CLI report only.
- Re-auditing any platform — this sub-project only structures and scores evidence the prior sub-project already gathered.
- Autonomy intervals/gates computation (`brain.autonomy.md` §5) — that requires incident/security-failure tracking this ecosystem doesn't have yet.
- The Owner-Free Operating Streak's interaction with the score (they're related but independent — the streak already has its own CLI in `services/intervention-log/`).
- Any change to the category weights or formula table once shipped — a future re-audit or new real capability updates `autonomy-signals.json` and re-running the CLI reflects it; the formula table itself only changes via a new sub-project design, not silently.
